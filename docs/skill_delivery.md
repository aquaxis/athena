# Skill delivery to the Agent — the settled mechanism (open item O-2)

## 1. The problem

`agent-cli` has **no skill placement mechanism** (spec §2.2; verified 0.23.0, `ATH-DEV-022`).
The Loader materializes the selected skills under
`<ATHENA_HOME>/var/instances/<instance_id>/skills/<id>/SKILL.md` (`ATH-SKILL-017`), but the
placed body is inert until the **Agent** reads it. Something must tell the Agent the material
exists and where to read it.

## 2. The settled mechanism

Delivery rides the two channels the Agent provably reads:

1. **The Instance's generated `.agent-cli/commands/`**. Per the 0.23.0 verification
   (spec §2.2.3), a slash-command body is expanded in `run` (REPL) only — and in the IPC
   route the **Agent reads the command file by absolute path as a procedure file**
   (`ATH-ACLI-017`). Delivery exploits exactly that fact: per placed skill, Skill
   generation writes `<agent_cli_dir>/commands/athena-skill-<id>.md`, whose entire content
   is one instruction — "read `<workspace>/skills/<id>/SKILL.md` (absolute path,
   version-pinned) and apply its procedure when required."
2. **The generated `persona.md`** — the Instance's working-convention section may carry the
   same reference for the level's standing duties (optional; generated by the same wiring).

The material itself is never injected into prose: the message channel carries the Agent's
instructions (risk-bearing skill use routes through approval — `ATH-SKILL-024`, P5-12), and
the Catalog only *names* skills (`ATH-SKILL-002` — the Core Agent never interprets the
package body).

## 3. The normative amendment (`ATH-SKILL-039`)

**ATH-SKILL-039** (MUST) Skill Manager は、Loader が配置した各 Skill に対し、Instance の
`​.agent-cli/commands/athena-skill-<id>.md` を生成し、内容として **絶対パスで** —
`<workspace>/skills/<id>/SKILL.md` を読むよう指示しなければならない。手順ファイルは
`​agent-cli` の IPC 経路の読み取り対象(`ATH-ACLI-017`)と同一の機構を用いる。生成先として
`​.agent-cli/skills/` 使用してはならない(`ATH-ACLI-015`)。

See the revision entry appended to the spec's 改訂履歴.
