# PCB SI（Signal Integrity）解析スキル

## 0. スキル概要

- **対象工程**: 基板開発の第5段階（検証）— 信号整合性（SI）解析。
- **適用タイミング**: アートワーク設計の主要配線完了後（配置完了段階でも早期解析可）。修正ループ時は修正後の再解析。
- **実行モード**:
  - **オーケストレーション連携**: `pcb-orchestrator` からレイアウト情報とともに起動（通常）。結果は統括を経由してアートワーク工程へ差戻し・合格合図として返される。
  - **単独実行**: ユーザーがレイアウト情報・制約・重要ネット一覧を提供して起動。
- **目的**: 高速信号の劣化要因（反射・減衰・クロストーク・ジッタ）を定量的に確認し、問題を修正指示書へ具体化することで、設計の信号整合性を保証する。

## 1. エージェントの役割と責任範囲

- **役割**: 解析対象ネットの選定、解析モデルの準備、SI解析の実行、判定、SI解析報告書と修正指示書の作成。
- **責任範囲**:
  1. 制約一覧の全重要ネットを、定められた基準で解析済みにする（網羅性の担保）。
  2. 判定基準を定量的に定義し、同じ条件で再実行可能な解析を設計・実施する。
  3. 指摘には必ず「修正の具体的方法」と「再検証条件」を付ける。
- **責任範囲外**: レイアウト修正の実施（アートワーク工程）、PI（電源）解析の実行（`pcb-pi-analysis`）、回路構成の変更判断。

## 2. 入力資料と前工程からの引き継ぎ情報

| 入力 | 形式 | 必須 | 出典 |
|------|------|------|------|
| レイアウト情報（構成・配置・層割り当て・配線幅・スタックアップ表） | Markdown（表）+ CADデータ | 必須 | `pcb-artwork-design` |
| 重要ネット一覧（速度・トポロジー優先度順） | Markdown | 必須 | 同上 |
| ネットリスト | CAD標準 | 必須 | `pcb-schematic-design` |
| ネット属性・制約（インピーダンス・トポロジー・長さ） | 表 | 必須 | 同上 |
| ICのドライバ特性（プル強度・エッジ速度）・IBIS/SPICEモデル | IBIS/SPICE/PDF | 条件付き（高速IC） | 人が提供（C） |
| 電源ドメイン・電力予算（IO電圧・基準） | 表 | 必須 | `pcb-system-design` |
| グランドデザイン仕様書（性能要求） | Markdown | 必須 | `pcb-grand-design` |

**受領確認手順**: ①スタックアップ表（εr・厚さ・銅厚）が揃っていること ②重要ネット一覧と制約値が一致していること ③必要なドライバモデルが入手可能か（不備時は簡易モデルで解析し、精度限界を明記）を確認。

## 3. 詳細な作業手順

分類: [A=自動化 / B=エージェント実行＋人の承認 / C=人が実行]

1. **[A] 入力の受領確認と網羅性チェック**。
2. **[A] 解析対象ネットの選定**: 重要度順に①クロック系 ②高速 シリアル/並列バス（DDR等） ③差動ペア ④高速 高傾斜信号・スイッチング大電流（リターン影響） ⑤それ以外の制約ネット を選定する。
3. **[A] 解析モデルの準備**: IBISをダウンロード・検証、またはドライバの簡易モデル（エッジ速度・出力抵抗）を作成し、限界を明記する。エッジ速度から帯域上限 `BW ≈ 0.35 / tr` を求める。
4. **[A] 解析プランの立案と承認**: 対象ネット・解析項目・判定基準・実行環境を一覧化して提示する。**B（承認ゲート①）**: 解析プラン。
5. **[A] 事前解析（トポロジー・遅延）**: 構成の確認、伝搬遅延概算 `t_pd ≈ √(L×C) × 長さ`（ER時に全体遅延の整合）を行う。
6. **[A] 反射解析**: 終端整合・オーバーシュート/アンダーシュートを波形で評価。`Γ = (Z_端末 − Z0) / (Z_端末 + Z0)` の確認と、波形悪化箇所の特定。
7. **[A] クロストーク解析**: 近接区間のカップリング評価。NEXT/FEXT近似と、詳細解析（ツール使用時）。
8. **[A] タイミング解析**: セットアップ/ホールドマージン計算（遅延・スキュー・エッジレート・ジッタを含む）。DDR等のトポロジー整合（fly-by・T分岐）の確認。
9. **[A] アイ解析（SerDes等）**: アイ開口（目視相当の定量値をツール出力から取得）・BER目標（例: 1e-12）との比較。
10. **[A] モード・EMI観点の確認**: ラジエーションリスク要素（モード変換、リターン切れ目と信号の交差）を指摘リストへ追加する。
11. **[A] 合否判定と重大度分類**: 第4節の判定基準によりS/A/B/Cを付与する。
12. **[B] 報告書のレビュー**: SI解析報告書＋修正指示書の承認を得る（解析判定はB: 判定方針の確認）。**必須承認ゲート②**。
13. **[A] 決議（アートワークへの差戻しと合格合図）**: S/A級指摘がある場合、修正指示書を `pcb-artwork-design` へ差戻し（FR-1.7ループ）。この差戻しはA分類の実行であり、指摘・修正指示の承認は報告書受入（承認ゲート②）で済む。合格の場合、合格報告を統括へ返す。
14. **[A] 自己検証**: 第8節のチェックリスト適用。

## 4. 設計判断基準と計算方法

### 4.1 判定基準（既定値・要求で上書き可）

| 解析項目 | 既定判定基準（例） |
|----------|--------------------|
| オーバーシュート/アンダーシュート | IO電圧の±10%以内（例: 3.3V → ±0.33V） |
| クロストーク（後段型） | 信号スイングの10%未満（例: 1.0Vピーク→0.1V未満） |
| タイミング マージン | セットアップ/ホールドで単位周期の10%以上（データシート優先） |
| アイ（SerDes） | アイ高さ・幅の要求BER達成（供給側スペックとの整合確認） |
| モード変換 | 制約値（例: 3%以内、高精度は より厳格） |
| リターン切れ目 | 重要信号の直下のGND参照面が分割・切れ目となる場合に指摘（B以上） |

※ ユーザーからの要求値・データシート値がある場合は、そちらが優先し、その旨を判断記録に残す。

### 4.2 主な計算方法

- **伝搬遅延**: `t_pd = √(L'C') × ℓ`。マイクロストリップで `≈ 5.5 ps/in × √(εeff/4)` 目安。
- **特性インピーダンス**: アートワーク工程と同一式を用いる（整合確認のために再計算・突合）。
- **反射係数**: `Γ = (Z_L − Z0)/(Z_L + Z0)`。
- **クロストーク近似**: 近接長ℓと距離sから、NEXT/FEXT 定数を概算（係数は解析ツールの仕様・モデルから取得）。
- **帯域・エッジ速度**: `BW = 0.35 / t_r`、システムの有効帯域を幹線要求と比べる。

### 4.3 判断記録

判定基準の上書き・簡易モデル使用・解析除外とその根拠に判断記録を作成する。

## 5. 使用するEDA・解析ツール

| 用途 | ツール例 | 連携方式 | 自動化レベル |
|------|----------|----------|--------------|
| SI波形解析 | 市販SI解析ツール（3D/2.5D/伝送線路ソルバ。採用製品は制約記録で別途明記） | CLI実行 + 結果ファイル解析 | A（反復解析）/ B（判定） |
| 電子部分モデル・簡易解析 | ngspice（OSS） | コマンドライン実行 | A |
| IBISモデル管理 | メーカーの モデルダウン収集（ユーザー提供） | ファイル交換 | C |
| 数値処理・可視化 | Python（numpy/matplotlib等） | スクリプト | A |
| 簡易計算（波長・遅延・反射） | スクリプト | 任意 | A |

ツールが使えない環境では、理論式・Sパラメータに基づく手計算を用いて簡易評価し、精度限界を報告書に明記する（B承認）。

## 8. 検証方法と品質基準

### 8.1 チェックリスト

共通チェックリスト（`pcb-common` 第8.2節）に加えて:

- [ ] 重要ネット一覧の100%が解析済みまたは除外され、除外の場合判断記録あり。
- [ ] 各解析に判定基準（数値）とデータ出典が付けられている。
- [ ] 簡易モデルを使用した部分に精度限界が明記されている。
- [ ] 全指摘に修正の具体的方法と再検証条件がある。
- [ ] S/A級指摘は、アートワーク工程への差戻しとして処理されている。
- [ ] 4大品質基準（完全性・整合性・追跡可能性・検証可能性）を満たす。

### 8.2 自動検証

- 判定基準の照合をスクリプトで自動実行（波形特性値を基準値と比較）。
- 対象ネット表と解析実行ログの突合（実行漏れの検出）。

## 9. エラー発生時の対応

共通手順（`pcb-common` 第9節）に従う。本工程固有の注意事項:

1. **モデル不在**: IBISが入手不可のICは簡易モデル（エッジ速度・出力抵抗）を生成し、精度限界を明記してB承認を得る。S/A級判定には高精度モデルを要求する旨を記録する。
2. **解析値の異常**（例: 反射が物理的に成立しない値）: 入力データ（スタックアップ・エッジ率）を再確認し、データ誤りの原因分類として入力側へ連絡する。
3. **部品レールの誤配線検出**（SI解析で電圧異常を検出した場合）: 直ちにS級として修正指示を発行する（設計への即時差戻し）。
4. **判定基準が要求と矛盾**: 要求側（データシート・規格）を優先し、基準の上書き判断を判断記録に残す。

## 10. 次工程への引き渡し条件

### 10.1 アートワーク工程へ（修正指示時; FR-1.7ループ）

- [ ] 全S/A級指摘に「修正方法・再検証条件・影響範囲」が定義されている。
- [ ] 修正対象のネット・位置が特定可能な形（ネット名・配線区間）で表記されている。
- [ ] 共通引き渡しチェックリスト（`pcb-common` 第10節）が合格。
- [ ] 後続の再解析または報告に必要な代替入力（SI代替入力一式）が揃っていること: ①幾何計量表（スタックアップ・層割当・トレース幅/長さ・トポロジー・近接間隔）②ドライバ特性（IBIS/SPICEモデル、または立ち上がり時間＋出力インピーダンス＋レベル）③動作条件（電源電圧・振幅・クロック/タイミング仕様）④判定基準（オーバーシュート・クロストーク・マージン・BER目標）。いずれかの必須項目が入手できない場合、S/A級判定を前提とした推定は行わず、不足項目を列挙したデータ取得要求を出して停止する。

### 10.2 合格時（統括へ）

- [ ] 全対象ネットが判定基準を満たす（または妥当化承認済み）。
- [ ] 報告書のレビュー（承認ゲート②）が承認済み。
- [ ] 再解析の必要性（リターン影響・モード変換等）を評価し、残存リスクを記録している。
