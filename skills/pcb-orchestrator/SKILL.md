# PCB開発オーケストレーションスキル

## 0. スキル概要

- **対象工程**: 全工程の統括（管理）。
- **適用タイミング**: 新規・変更基板開発の全体実行、または中断したプロジェクトの再開、部分実行の指示時。
- **実行モード**:
  - **全体実行**: 自然言語の要求文から全工程を順次実行する。
  - **部分実行**: 「回路設計から実施」のように開始工程を指定して実行する。
  - **差戻し処理**: SI/PI解析の修正指示に基づくアートワーク工程の再実行。
- **本スキルの位置づけ**: 本スキル自体は設計作業を実行しない。各工程スキル（`pcb-grand-design`、`pcb-system-design`、`pcb-schematic-design`、`pcb-artwork-design`、`pcb-si-analysis`、`pcb-pi-analysis`）を起動し、受け渡しとゲート管理を行う統括ロールである。

## 1. エージェントの役割と責任範囲

- **役割**: ①要求の受理と作業の割り当て ②工程の順序制御 ③成果物の受け渡し管理 ④ゲート判定（引き渡し条件の確認） ⑤承認待ち・差戻しの管理 ⑥進捗報告とプロジェクト完了報告の集約。
- **責任範囲**:
  1. 各工程の成果物が、次工程の必須入力を満たすことを確認してから進行する。
  2. 承認ゲートで人間の承認を取得するまで進行を停止する。
  3. 状態（`workflow_state.md`）を常に最新に保つ。
  4. 判断記録・検証結果を集約し、最終報告書を生成する。
- **責任範囲外**: 各工程内の設計判断・解析実行（個別スキルの領域）、商業・ライセンス判断（人）。

## 2. 入力資料と前工程からの引き継ぎ情報

| 入力 | 形式 | 必須 | 説明 |
|------|------|------|------|
| 要求文（自然言語） | テキスト | 必須（全体実行時） | 作りたい基板の概要・性能・制約 |
| 既存の状態ファイル `workflow_state.md` | Markdown | 再開時に必要 | 進捗・ゲート状態の履歴 |
| 既存成果物（再開・部分実行時） | 成果物一式 | 条件付き | 完了済み工程の成果物 |
| ユーザーの指示（開始工程・優先事項等） | テキスト | 任意 | 部分実行の起点指定 |

独自の前工程からの引き継ぎ情報は持たないが、各工程間の受け渡しは第4節（工程間インターフェース）に従う。

## 3. 詳細な作業手順

分類: [A=自動化 / B=エージェント実行＋人の承認 / C=人が実行]

### 3.1 開始手順

1. **[A] 状態の確認**: 既存の `workflow_state.md` があれば読み込み、進捗を復元する。無ければ新規作成する。
2. **[A] 実行計画の作成**: 開始工程と実行順序（第4節パイプライン）を決め、ユーザーに提示する。
3. **[B] 実行計画の承認**: 開始時の計画承認を得る。**必須承認ゲートO（開始）**。

### 3.2 本進行手順（以下を全工程完了まで繰り返す）

1. **[A] 次工程の決定**: 状態ファイルから「未着手」または「差戻し」の最も手前の工程を選ぶ。
2. **[A] 工程スキルの起動**: 決定した工程の `SKILL.md` を読み込み、該当スキルとして動作する（または起動する）。必要な入力（前工程成果物）を引き渡す。
3. **[A] 成果物の受領と確認**: 作業完了後、成果物を受け取り、該当工程の第10節（引き渡し条件）と共通チェックリスト（`pcb-common` 第10節）でゲート判定する。
4. **[A] ゲート判定の処置**:
   - **合格** → 状態を「完成」に更新し、次工程へ進む。
   - **不合格** → 状態を「差戻し」に更新し、不具合記録と修正指示を当該工程へ返す（再実行）。
5. **[B] 承認ゲートの管理**: 各工程の必須承認ゲートで、承認を得るまで進行を停止する。承認記録を状態ファイルに追記する。
6. **[A] 差戻しループ（FR-1.7）**: SI/PI解析の修正指示書を受けた場合、アートワーク工程を「差戻し」状態で再起動し、修正・再検証・再解析を繰り返す。同一指摘が**初回を含めて3回目**に達した場合、エスカレーション（第9節）を行う。

### 3.3 完了手順

1. **[A] 最終報告書の集約**: 全工程の報告書・判断記録・検証結果・承認履歴から `プロジェクト完了報告書.md` を生成する。
2. **[B] 完了承認**: 報告書の提示と承認の取得。**必須承認ゲートZ（完了）**。
3. **[A] 状態ファイルの最終更新**（全工程「完成」）。

### 3.4 部分実行・単独実行の支援

1. **[A] 依頼内容の分解**: 対象工程と、その工程の必須入力（該当SKILL第2節、第10節）を特定する。
2. **[A] 入力の確認**: 必須入力が揃っていない場合、必要な成果物・情報の提供をユーザーに要求する（前工程を実行する選択肢も提示する）。
3. **[A] 実行と報告**: 該当スキルを実行し、成果物とゲート判定結果を報告する。全体フローへの合流を勧める（判断記録は必須入力として保存）。

## 4. 工程間インターフェース（順序と成果物の受け渡し）

### 4.1 パイプライン

```
1. pcb-grand-design → 2. pcb-system-design → 3. pcb-schematic-design → 4. pcb-artwork-design ⇄ {5. pcb-si-analysis, 6. pcb-pi-analysis} ⇄ 4（修正ループ）
 共通基盤: pcb-common（全工程から参照）  統括: 本スキルが状態とゲートを管理
 横断支援（パイプライン外）: pcb-parts-research ← グランド/システム設計の制約確定後またはデータ要求時に起動 → 候補データを pcb-schematic-design へ引き渡す
```

### 4.2 成果物の受け渡し表

| From → To | 引き渡し成果物 | ゲート条件の出典 |
|-----------|----------------|------------------|
| grand-design → system-design | グランドデザイン仕様書（ターゲット仕様・制約一覧・リスク） | grand-design 第10節 |
| system-design → schematic-design | システム設計仕様書（ブロック・接続・電源） | system-design 第10節 |
| parts-research → schematic-design（横断支援） | 部品調査パッケージ・候補表（出典つき候補データ・入手性/ライフサイクル調査込み） | parts-research 第10節（横断支援: `pcb-common` 第6節 共通ゲート③適用表の A分類機械検証） |
| schematic-design → artwork-design | 回路設計パッケージ（ネットリスト・BOM・制約一覧） | schematic-design 第10節 |
| artwork-design → si-analysis / pi-analysis | レイアウト情報・スタックアップ・重要ネット/電源一覧 | artwork-design 第10.1節 |
| si-analysis / pi-analysis → artwork-design | SI/PI解析報告書・修正指示書 | 解析スキル第10.1節 |
| artwork-design → 完了系（リリース） | アートワーク設計パッケージ・製造データ一式・解析合格報告 | artwork-design 第10.2節 |
| 全工程 → 統括 | 判断記録・レビュー結果・承認記録 | 各SKILL第7・8節 |

### 4.3 実行順序の詳細ルール

1. SI/PI解析は、アートワークの配置・主要配線完了後、並列または直列で実行できる。
2. `pcb-parts-research` はパイプライン工程ではなく横断支援である: グランド／システム設計の制約確定後に前倒しで起動するか、回路設計工程からのデータ要求に応じて起動する。状態は工程表に「横断支援」として記録し、成果物（`03_parts/`）の所在を回路設計工程の行から参照する。
3. 別の差戻しが同時に発生した場合、先にS/A級重大度の高い指摘を処理する（詳細は各工程の重大度定義に従う）。
4. 差戻し回数に上限はないが、同一指摘が初回を含めて3回目に達した時点でエスカレーションする。

## 5. 状態管理（workflow_state.md）

状態ファイルは下部テンプレートに従い、全工程の状態・ゲート履歴・判断記録の所在を記録する。

```markdown
# workflow_state.md

## プロジェクト概要
- プロジェクト名:
- 開始日時:
- 要求文の所在:

## 工程状態
| 工程 | スキル | 状態 | 成果物の所在 | 承認ゲート | 最終更新 |
|------|--------|------|--------------|------------|----------|
| 1 | pcb-grand-design | 未着手 / 実行中 / 承認待ち / 完成 / 差戻し | | ①②③ | |
| ... | ... | ... | ... | ... | ... |

## ゲート履歴
| 日時 | 工程 | ゲート | 判定 | 承認者 |

## 差戻し履歴
| 日時 | 送信元 | 送信先 | 指摘内容（重大度） | 処理結果 |
```

**状態値**: 未着手・実行中・承認待ち・完成・差戻し。状態変更は必ず履歴に記録する。

## 6. 自動化する処理と人間が承認する処理

| 処理 | 分類 |
|------|------|
| 状態管理・スキル起動・成果物受領・ゲート判定・ループ制御・報告書生成 | A（自動） |
| 開始承認・各工程承認ゲートの通過・完了承認 | B（人が承認） |
| 商業判断・ライセンス・納期調整・データ/モデルの提供 | C（人が実行） |

**停止ルール**: 以下の場合は進行を停止し、ユーザーに報告する。
- 承認ゲートで承認が得られない。
- 差戻しループで同一指摘が初回を含めて3回目に達した。
- 手順書にない判断が必要になった。

## 7. 成果物とファイル形式

- **成果物1**: `workflow_state.md`（プロジェクトルート）— 進捗とゲート履歴の管理ファイル。本スキルの常設成果物。
- **成果物2**: `<project_root>/プロジェクト完了報告書.md` — 構成: 目次、実行サマリ（工程・成果物一覧）、各工程報告書の要旨、設計判断記録の一覧（工程ごとへの参照）、検証結果（ERC/DRC/解析）のサマリ、承認記録、残存リスク、変更履歴、版数。
- 各工程の成果物（仕様書・パッケージ・報告書）は、各工程スキルの定義に従う。統括は差し替えない（所在を参照するのみ）。

## 8. 検証方法と品質基準

### 8.1 チェックリスト

共通チェックリスト（`pcb-common` 第8.2節）に加えて:

- [ ] 全工程が「完成」または「妥当化承認済み差戻し解消」状態である。
- [ ] 全ゲート判定の記録（合格／不合格と理由）が履歴にある。
- [ ] 全承認ゲートの承認記録が揃っている。
- [ ] 差戻しループの全記録（指摘→修正→再検証→再判定）が履歴にある。
- [ ] 完了報告書が、全成果物の所在を網羅している。
- [ ] 4大品質基準（完全性・整合性・追跡可能性・検証可能性）を満たす。

### 8.2 自己検証方法

- 状態ファイルの整合性（状態値とゲート履歴の一致）を確認する。
- 各工程の成果物が第10節条件を満たすかを確認済みか、ゲート履歴から再確認する。
- 未解決の差戻し・未承認ゲートのゼロを確認する。

## 9. エラー発生時の対応（エスカレーション）

共通手順（`pcb-common` 第9節）に従い、統括として下記を管理者に付加する:

1. **差戻しの無限ループ防止**: 同一指摘が初回を含めて3回目に達した時点で、対象工程のエスカレーションを行う（問題の根本原因・解決の選択肢を提示して人の決定を仰ぐ）。
2. **スキル異常**（工程スキルが成果物を生成できない・エラー）: 状態を「差戻し」または「停止」にし、エラー内容と必要な人的支援を報告する。
3. **承認待ちの長期化**: 状態を「承認待ち」に保持し、督促とともに未承認事項の一覧を提示する。
4. **入力不足による進行不能**: 必要な入力と、前工程実行の選択肢を提示して停止する。

## 10. プロジェクト完了時の引き渡し条件

本スキルの「次工程」は、設計リリース後の製造・量産準備（を含む）である。

- [ ] 全工程が完成状態である。
- [ ] 全承認ゲートが承認済みである。
- [ ] SI/PI解析が合格し、S/A級指摘が全て解消済みである。
- [ ] 完了報告書が生成・承認済みである（承認ゲートZ）。
- [ ] 製造データ一式（Gerber・drill・組立図・P&P・3D）が全て揃っている。
- [ ] 共通引き渡しチェックリスト（`pcb-common` 第10節）全項目合格。
- [ ] 残存リスクとネクストアクション（製造発注・試作・評価）が明記されている。

## 付録: 共通ルールの参照（`pcb-common`）と個別スキルの参照

- 共通ルール: `../pcb-common/SKILL.md` を参照（用語・判断記録・チェックリスト・エラー対応・引き渡し）。
- 個別スキル: 本スキルから各工程 `../<skill-dir>/SKILL.md` を参照・起動する。起動時は該当スキルの第0〜10節に従い、成果物とゲート条件も該当スキルの規定を用いる。
- 上書き規則: 本スキルの規定と個別スキル・共通ルールの矛盾時は、**個別スキルの成果物規定が優先**し、共通事項は `pcb-common` に従う。本スキルの統括手順（順序・状態管理）は、個別事項が無い範囲で統括規定を適用する。

| 場面 | 参照節 |

| エラー対応・重大度 | 第9節 |
