# PCBシステム設計スキル

## 0. スキル概要

- **対象工程**: 基板開発の第2段階（システム設計／ブロック設計）。
- **適用タイミング**: グランドデザイン設計の承認後、回路図設計開始前。
- **実行モード**:
  - **オーケストレーション連携**: `pcb-orchestrator` からグランドデザイン成果物とともに起動される（通常）。
  - **単独実行**: ユーザーが目標仕様・制約一覧（グランドデザイン仕様書または同等資料）を直接提供して起動する。
- **目的**: 機能構成と接続・電源の骨格を確定し、回路設計で迷いが生じないレベルまで構造を具体化する。

## 1. エージェントの役割と責任範囲

- **役割**: 機能ブロックの分割定義、ブロック間接続の定義、電源ドメイン設計、電力予算の作成、クロック体系の設計、主要素子クラスの選定方針決定、配置構想の作成。
- **責任範囲**:
  1. ターゲット仕様・制約の全項目がシステム構成に反映されていることを保証する。
  2. ブロック間の信号・電源・制御の接続を全て定義する。
  3. 電源ツリーと各ドメインの電圧・電流・許容リップルを定量定義する。
  4. 主要な設計判断（分割方針・IC構成・バス速度等）に判断記録を残す。
- **責任範囲外**: 具体的な回路定数の決定・作図（回路図設計工程）、実配線・スタックアップ確定（アートワーク工程）。

## 2. 入力資料と前工程からの引き継ぎ情報

| 入力 | 形式 | 必須 | 出典 |
|------|------|------|------|
| グランドデザイン仕様書 | Markdown | 必須 | 前工程（`pcb-grand-design`） |
| └ ターゲット仕様（定量的） | 表（Markdown） | 必須 | 同上 |
| └ 制約一覧（技術・商業・規制） | 表 | 必須 | 同上 |
| └ リスク登録簿 | 表 | 必須 | 同上 |
| 概念ブロック図（ある場合） | Markdown（Mermaid）/画像 | 任意 | 同上 |
| ユーザー指定の追加要求・制約 | テキスト | 任意 | 単独実行時に受領 |

**受領確認手順**: ①ターゲット仕様の全項目が数値・単位付きであること ②制約一覧が完備していること ③判断記録と承認記録が揃っていることを確認する。不成立の場合は前工程への差戻し判断（第9節）を行う。

## 3. 詳細な作業手順

分類: [A=自動化 / B=エージェント実行＋人の承認 / C=人が実行]

1. **[A] 入力の受領確認と欠落チェック**: 第2節の条件を確認し、判定結果を記録する。
2. **[A] 機能分解の候補生成**: ターゲット仕様の各要求を満たす機能群を洗い出し、ブロック候補を生成する（FR-1.1・FR-1.2の成果を構造化へ反映）。
3. **[B] 機能ブロック分割と主要素子クラスの決定**: 提案（機能ブロック一覧＋主要素子クラス候補）を提示し、ユーザー承認を得る。**必須承認ゲート①（ブロック分割の確定）**。
4. **[A] ブロック間接続の定義**: 信号フロー（データ・制御・アナログ）、バス幅・速度、方向、個数を一覧表にする。
5. **[A] 電源ドメイン設計**: 電圧レベル、ドメイン数、系統（アナログ/デジタル/RF/IO等）を定義する。レベルシフタ・分離要否を判断する。
6. **[A] 電力予算の作成**: 第4.2節の計算方法で各ドメインの電流・消費電力を積算し、電源ツリーを描く。
7. **[B] 電源・分割構成の承認**: 電源ツリーとドメイン分離方針の承認を得る。**必須承認ゲート②（電源ドメイン・電力予算）**。
8. **[A] クロック体系の設計**: クロック源、配布、必要周波数、同期方式（同期/非同期）を定義する。
9. **[A] 配置構想の作成**: 機能ブロックのボード上のおおまかな位置関係、コネクタ位置、アナログ・デジタル・RFの分離方針を決める。
10. **[A] 自己検証**: 第8節のチェックリストを適用する。
11. **[B] 引き渡し**: 第10節の条件確認後、回路図設計工程へ引き渡す。**必須承認ゲート③**（この承認が `pcb-common` ③「引き渡し直前」を兼ねる）。

## 4. 設計判断基準と計算方法

### 4.1 ブロック分割の判断基準

| 判断事項 | 判断基準（例） |
|----------|----------------|
| 統合 vs 分離 | 配線経路の単純さ・相互接続の複雑さ・熱密度を比較。高密度・高発熱部は分離を検討。 |
| アナログ/デジタルの分離 | SNR要求が高い（例: SNR > 60dB の前段）場合、別ドメイン。 |
| プロセッサ構成 | 必要演算量（MIPS/FLOPS推定）＜単体IC能力なら1IC、超えるなら分散。 |
| バス種別 | 距離・速度・負荷数から選定（低速I2C/SPI、高速はLVDS/SerDes）。 |

### 4.2 主な計算方法

- **電力予算**: `P_block = I_rail × V_rail × 活動率`。各ICはデータシートの典型値×活動率で概算し、計算の根拠を明記する。
- **電流容量**: `I_max = P / V`（余裕率 1.2〜1.5を乗ずる）。
- **ターゲット・リップル**: 各レールについてリップル許容%（データシートから）を抽出。
- **ジャンクション温度**: `Tj ≈ Ta + P × θJA`（グランドデザイン環境温度を用いる）。
- **スループット整合**: `必要データレート ≤ バス帯域 × (デューティ × 有効率)`。

### 4.3 判断記録

分割方針・IC構成・バス構成・電源構成の各決定に判断記録（`pcb-common` 第7.3節）を作成する。

## 5. 使用するEDA・解析ツール

## 8. 検証方法と品質基準

### 8.1 チェックリスト

共通チェックリスト（`pcb-common` 第8.2節）に加えて:

- [ ] ターゲット仕様の全項目に対して、「どのブロックがその要求を担うか」の対応表が存在する。
- [ ] 全てのブロック間接続に、信号名・方向・速度・負荷数・電気仕様（レベル）が定義されている。
- [ ] 電源ツリーの全レールに電圧・電流・リップル許容値が記載されている。
- [ ] 電力予算の総計がターゲット仕様の消費電力上限を超えていない（超える場合は判断記録で妥当化）。
- [ ] クロックの全ての受信側が、供給元と周波数整合している。
- [ ] 全ブロックの配置構想が、制約（外形・コネクタ・放熱）と矛盾しない。
- [ ] 4大品質基準（完全性・整合性・追跡可能性・検証可能性）を満たす。

### 8.2 自動検証

- 接続一覧の参照整合（無参照・重複名チェック）をスクリプトで確認する。
- 電力予算の積算をスクリプトで再計算し、人手計算と突合する。

## 9. エラー発生時の対応

共通手順（`pcb-common` 第9節）に従う。本工程固有の注意事項:

1. **入力不備の検出が主なエラー原**: ターゲット仕様に定量的でない項目がある場合、前工程へ差戻し判断を記録し、ユーザーに確認する。軽微な欠落（単位欠等）は本工程で補完し、判断記録に記載する。
2. **電力予算の超過**: 電力上限を超えた場合、①省電力な構成への変更案 ②冷却手段の追加案 ③上限の再交渉案を併記してユーザーに提示する。
3. **ブロック間の電位整合エラー**（例: 3.3V出力と1.8V入力の直結）: レベルシフタ追加案または別IC選定案を提示し、修正後、接続一覧を再検証する。

## 10. 次工程への引き渡し条件

以下を全て満たした場合、回路図設計工程（`pcb-schematic-design`）へ引き渡す。

- [ ] 機能ブロック一覧と接続一覧が完備している。
- [ ] 電源ドメイン（電圧・電流・リップル）が定量的に確定している。
- [ ] 電力予算が承認済みである（承認ゲート②）。
- [ ] クロック体系が確定している。
- [ ] 配置構想が確定している。
- [ ] 共通引き渡しチェックリスト（`pcb-common` 第10節）が全項目合格。
- [ ] 承認ゲート①②③の承認記録が揃っている。
