# PCB回路図設計スキル

## 0. スキル概要

- **対象工程**: 基板開発の第3段階（回路設計／スケマティック・キャプチャ）。
- **適用タイミング**: システム設計仕様書の承認後、PCBアートワーク設計開始前。
- **実行モード**:
  - **オーケストレーション連携**: `pcb-orchestrator` からシステム設計成果物とともに起動（通常）。
  - **単独実行**: ユーザーがシステム設計仕様書（または同等資料）を提供して起動。
- **目的**: システム設計の骨格を、部品レベルの実際の回路に落とし込み、検証済みのネットリストとBOMをアートワーク工程へ引き渡す。

## 1. エージェントの役割と責任範囲

- **役割**: 回路図の作成、部品の選定（候補提示と確定）、ネット属性・設計制約の定義、回路検証（ERC・DRC）、ネットリスト・BOMの生成。
- **責任範囲**:
  1. ブロック図の全接続が回路図に反映されていることを保証する。
  2. 全ネットに、信号クラス・制約（速度・トポロジー・インピーダンス等）を付与する。
  3. ERC/DRC クリアを担保する。
  4. 部品選定の根拠（データシート値・要件整合・調達可否）を判断記録として残す。
- **責任範囲外**: 基板の物理配置・スタックアップ・実際の配線（アートワーク工程）、SI/PI解析判定。

## 2. 入力資料と前工程からの引き継ぎ情報

| 入力 | 形式 | 必須 | 出典 |
|------|------|------|------|
| システム設計仕様書（ブロック一覧・接続一覧・電源ドメイン・電力予算） | Markdown | 必須 | 前工程（`pcb-system-design`） |
| └ ブロック図 | Mermaid / 画像 | 必須 | 同上 |
| └ 電源ツリー（電圧・電流・リップル許容） | 表 | 必須 | 同上 |
| グランドデザイン仕様書（参照・制約確認用） | Markdown | 必須 | 前々工程 |
| コンセプト・対象ICのデータシート | PDF/テキスト | 必須（主要IC） | 人が提供（C）。または `pcb-parts-research` 成果物の出典つきスペック記録 |
| 部品調査パッケージ・候補表（出典つき候補データ・入手性/ライフサイクル調査込み） | Markdown + CSV | 条件付き | 横断支援（`pcb-parts-research`、`03_parts/`）— 実行済みの場合は本工程の入力として活用する |
| 既存回路資産・ライブラリ | 電子CADデータ | 任意 | 人が提供 |

**受領確認手順**: ①接続一覧に未定義速度・レベルがないこと ②電源レールに電圧・電流が揃っていること ③主要ICのデータシートが入手可能であることを確認。不備時は第9節の差戻し判断を行う。

## 3. 詳細な作業手順

分類: [A=自動化 / B=エージェント実行＋人の承認 / C=人が実行]

1. **[A] 入力の受領確認と欠落チェック**。
2. **[A] 回路CAD環境の確認**: 利用可能なツール（KiCad等）とライブラリの有無を確認し、環境決定を記録する。
3. **[C] 部品候補の入手**: 主要ICはデータシートを人が提供する。調達条件・在庫情報も依頼する。`pcb-parts-research` が実行済みの場合、その候補表・スペック記録を本手順の入力とする（「部品調査パッケージ・候補表」の行を参照）。
4. **[A] パーツライブラリの構築**: CADライブラリ（シンボル）の不足分を作成・確認する。
5. **[A] 部品選定の候補作成**: 電気仕様・パッケージ・調達性・コストで候補を比較し、第一候補を提示する。
6. **[B] 主要部品の承認**: 主要IC・コネクタ・電源ICの選定承認を得る。**必須承認ゲート①（部品選定）**。
7. **[A] 回路作図**: ブロックごとに回路を作図する（アナログ前段・デジタル本体・電源・I/O・保護回路）。共通の変更手順（`pcb-common` 第3.2節）を設計データ変更時に適用する。
8. **[A] デカップリング・保護回路・テストポイントの追加**: 第4節の計算に基づき容量・抵抗値を算定し実装する。
9. **[A] ネット属性の設定**: 信号クラス（高速・クロック・アナログ等）、トポロジー、インピーダンス制約、差動ペア指定、長さ制約をネット属性として設定する。
10. **[A] ERC/DRC実行**: 回路CADのERC・DRCを実行し、全警告を解消または妥当化（判断記録）する。
11. **[A] 参照整合検証**: ブロック図（システム設計）とネットリストを突合する（第8節）。
12. **[B] 回路検証結果の承認**: ERC/DRC結果と突合結果、および回路図PDFを提示し承認を得る。**必須承認ゲート②（リリースレビュー: アートワーク開始直前）**。
13. **[A] ネットリスト・BOM生成**: ネットリスト（`.net` 等）とBOM（CSV）を生成する。
14. **[A] 自己検証と引き渡し**: 第10節の条件を確認し、アートワーク工程へ引き渡す。引き渡し自体の承認は、既に承認済みのリリースレビュー（承認ゲート②）が共通ゲート③「引き渡し直前」を兼ねる（別個のゲート③は設けない）。

## 4. 設計判断基準と計算方法

### 4.1 部品選定の判断基準

| 判断事項 | 判断基準（例） |
|----------|----------------|
| IC選定 | 電気仕様（速度・精度・レール）の充足、周辺部品の単純さ、調達性・寿命情報、パッケージと放熱 |
| コネクタ | 電流容量（1.5倍余裕）、耐圧、構造（取付強度）、加工仕様 |
| 受動部品 | 誤差・温度特性・耐圧、参照の安全性（2次供給可否） |

### 4.2 主な計算方法

- **デカップリング容量（ターゲットインピーダンス法）**:
  `Z_target = V_ripple / I_transient`。周波数fにおける必要容量 `C = 1 / (2π f Z_target)` を目安に、複数容量・バルク容量を各電源ピン/レールへ配分する。
- **プルアップ・プルダウン**: `R_min = (V_H事象時漏電圧降) / I_sink`、`R_max = V_pull / I_leak` を考慮し、標準値を選択。
- **分圧・レベルシフタ**: ロジックV_IH/V_ILマージンを1.2倍以上確保するよう分割比を選定する。
- **電源IC選定**: `I_rating ≥ I_max × 1.5`、リード時間・周辺部品数を比較判断記録に残す。
- **クロストーク誘発ポリシー**: 急峻信号・クロックには直列終端抵抗（`R_series ≈ Z0 - R_out`）を初期値で付与する。

### 4.3 判断記録

部品選定・回路方式（トポロジー）選択・保護設計方針・制約値の決定に判断記録を作成する。

## 5. 使用するEDA・解析ツール

| 用途 | ツール例 | 連携方式 | 自動化レベル |
|------|----------|----------|--------------|
| 回路作図 | KiCad、市販回路図キャプチャCAD | GUIまたはスクリプト（Python等）/ ファイル交換 | B（作図判断）/ A（生成） |
| ERC/DRC | KiCad CLI（`kicad-cli sch erc`）、各CADのチェック機能 | CLI | A |
| ネットリスト出力 | `kicad-cli sch export netlist`、使用中CADのエクスポート機能（CLI/スクリプト） | CLI / スクリプト | A |
| BOM出力 | CADのBOMエクスポート、スクリプト変換 | CLI / スクリプト | A |
| 部品検索（自工程内の補完照会） | `pcb-parts-research` の候補データを第一入力とし、不足分のみメーカー手検索・在庫API（ユーザー提供） | 候補データ受入＋任意照会 | A（受入・突合）/ C（補完照会） |

ツール利用不可の環境がある場合、ネット表（YAML/CSV形式）をテキストで作成し、ユーザーCADへの取り込みをC作業として依頼する。

## 6. 自動化する処理と人間が承認する処理

| 手順 | 分類 |
|------|------|
| 受領確認・ライブラリ構築・候補作成・作図・属性設定・ERC/DRC・突合・生成・部品調査データの受入・突合 | A（自動実行） |
| 部品選定・リリースレビュー（アートワーク前; 引き渡し承認を兼ねる=共通ゲート③） | B（承認ゲート①②） |
| データシート・調達情報の提供 | C |

## 7. 成果物とファイル形式

- **成果物1**: `03_schematic/回路設計パッケージ.md` — 構成: 目次（成果物一覧）、部品選定根拠一覧、ネットクラス・制約一覧表、デカップリング配置一覧、ERC/DRC結果と対応、突合結果、回路変更履歴、不具合記録、判断記録、レビュー結果、承認記録、版数と変更履歴。
- **成果物2**: 回路図ソースファイル（例: `.kicad_sch`、または使用中CAD固有のソース形式）— CAD環境の成果物。
- **成果物3**: ネットリスト（例: `03_schematic/<project>.net`、KiCad netlist等のCAD標準形式）。
- **成果物4**: `03_schematic/BOM.csv`（項目: 参照番号, 値, パッケージ, MPN, 数量, メーカー, 備考）。
- 二進数のCADデータはパッケージMarkdownから参照する。判断記録・レビュー結果は共通ルール（`pcb-common` 第7節）に従う。

## 8. 検証方法と品質基準

### 8.1 チェックリスト

共通チェックリスト（`pcb-common` 第8.2節）に加えて:

- [ ] ブロック図の全接続が回路図に反映されている（漏れなし）。
- [ ] 全ネットに信号クラスと制約（該当するもの）が設定されている。
- [ ] 全電源レールに、システム設計の電圧・電流・リップル値が反映されている。
- [ ] ERC/DRCの全警告が解消または判断記録で妥当化されている。
- [ ] BOMの全項目にMPN・メーカーが記載されている。
- [ ] `pcb-parts-research` の候補データを用いる場合、BOMのMPN・メーカーが候補表と突合済みである（乖離は判断記録で説明）。
- [ ] 4大品質基準（完全性・整合性・追跡可能性・検証可能性）を満たす。

### 8.2 自動検証

- **突合検証**: 接続一覧（システム設計）とネットリストを名前・属性で突合し、未採番・重複・レベル不整合を検出する。
- **電源整合**: 電源レール別に、接続先デバイスのレール名一致を検査する。
- **BOM整合性**: BOMと回路図の参照番号集合の一致を確認する。

## 9. エラー発生時の対応

共通手順（`pcb-common` 第9節）に従う。本工程固有の注意事項:

1. **ERC警告の処分方法**:実際の設計上問題ない警告（例: Nets without a net label）は妥当化する場合も必ず判断記録を作成する。重大（電源ショート等）はSとして直ちに修正する。
2. **突合不一致**: ブロック図との不一致は原因分類し、個別に特定（回路漏れ・ブロック図誤り）。ブロック図誤りの場合は前工程への差戻し判断を記録する。
3. **部品調達不可**: 代替部品候補を再評価し、承認ゲート①の再承認を得る。
4. **ライブラリ不整合**: パッド情報の誤りが疑われる部品は、アートワーク工程への引き渡し前に修正・再検証する。

## 10. 次工程への引き渡し条件

以下を全て満たした場合、PCBアートワーク設計工程（`pcb-artwork-design`）へ引き渡す。

- [ ] 回路図ソース・ネットリスト・BOMが生成されている。
- [ ] ERC/DRCクリア（または妥当化記録済み）。
- [ ] ネットクラス・長さ・トポロジー・インピーダンス等の制約一覧が完備している。
- [ ] 参照（ブロック図）突合がクリアし、不一致が解消されている。
- [ ] リリースレビュー（承認ゲート②）の承認が得られている。
- [ ] 共通引き渡しチェックリスト（`pcb-common` 第10節）が全項目合格。
- [ ] ネイティブEDAデータが作成できない場合、受け渡しに合意した代替形式（業界標準ネットリスト、またはピン単位の完全なネット表＋部品表）を用い、その代替形式の受入れ条件（後続工程が全接続・属性を再構築でき、ブロック図突合を通ること）を満たしている。満たせない場合は引き渡しを停止し、エスカレーションする。
- [ ] 承認ゲート①②の記録が揃っている（リリースレビュー②が共通ゲート③「引き渡し直前」を兼ねる）。
